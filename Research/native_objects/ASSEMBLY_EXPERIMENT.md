# Assembly 010 — explicit repeated-component arrangements

Freeze before paid dispatch. The same model (gpt-6-sol medium), compact geometry
output schema, geometry executor and primitive/boolean library remain in place.
The request interpreter adds a small assembly-decision list tied to existing IDs.
No object recipes, per-output repairs, animation, GPU calls or paid judging model.

Each repeated entity needs placement AND orientation decisions. Source-bound required,
optional, design-choice, evidence-required and unsupported distinctions remain. Missing
count-based groups fail extraction; unforeseen repetition in the plan fails coverage.
Unsupported group rules remain explicit and required unsupported blocks execution.

Supported new placement checks: equal-radius/equal-gap radial arrays with a common
height around a declared reference, and equally spaced collinear arrays along an
object axis. Orientation uses signed object axes or undirected parallelism. Existing
radial-outward geometry checks can supply the orientation for outward-pointing members.
There is no inference that a complete decision list establishes complete understanding.

Bindings cover every group member once using real, mated geometry features. Signed or
parallel orientation and placement use the same ports. Requirements, group membership,
patterns, policy and admitted port binding refs stay fixed across a bounded repair.
Root rotation/translation is irrelevant to object-relative checks. Fixed tolerances:
0.5 mm position floor, 5% spacing/radius tolerance, 10 degrees for axes/angular gaps.
Actual solved geometry is measured. Topology, arrangement and other failures remain
separately reported. Passing declared checks does not prove proper feature semantics.

## Frozen cases and pass criteria

`arrangement_cases_010.json` contains the exact requests, proposed role catalogs and
hidden scorecard. Only requests, catalog IDs and source units go to extraction; the
scorecard never enters model context. The geometry planner sees only frozen interpreted
requirements/decisions, the original request, and normal repair feedback.

- Original generic quadcopter: unchanged request and seven proposed roles. Preserve
  four arms/motors/propellers, radial layout in the object's horizontal plane, radial
  arm orientation, and common vertical motor/propeller axes. Either signed vertical
  direction is acceptable. Inspect/explode remain required. This tests a conventional
  layout, not every valid tilted/asymmetric alternative or autonomous part discovery.
- Cooling fan bank: three frames and three rotors side by side in a horizontal,
  equally spaced row, all facing front. Static inspection/separation, no airflow claim.
- Two-driver tabletop speaker: two matching drivers side by side at the front,
  facing forward, with separate inspectable components. No sound or animation claim.

Each family must pass the predeclared extraction assertions, complete typed coverage,
ALL old geometry checks and ALL new arrangement checks. Inspect assembled/exploded
renders separately for recognizable components, coherence, and useful separation.
Visual failure remains failure even when numeric checks pass. Preserve every failed
attempt. The three cases are one bounded comparison, not a consistency estimate.

## Paid bounds and decision rule

Three extractions, at most two plans per case; first plans precede repairs. Extraction
3,072 output tokens/$0.045 maximum, planning unchanged 12,288/$0.16 maximum. Batch
ceiling $1.10, conservative prior research allowance $3.70, aggregate ceiling $5,
shared daily ceiling $6. Quote actual input tokens and reserve maximum output first.
A quote/admission/transport/funding error stops further network calls. Incomplete or
uncertain calls are retained and never automatically retried. Old uncertain holds remain.
Extraction deadline 120 seconds, planning 240. No provider/model or cap changes.

Proceed to more families only if group interpretation AND measured realization work
across these families. If interpretation omits/misstates arrangements, fix that layer.
If declared groups survive but geometry fails, use the exact failed checks to identify
what remains. Do not loosen a checker or add a case-specific layout to obtain a pass.
A disconnected speaker housing remains a topology failure. Do not spend further merely
to produce one attractive drone. No production/Quest promotion from this experiment.
