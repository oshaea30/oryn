# Assembly 012 — recoverable requests and bounded local repairs

The same fan, speaker and drone requests/catalogs remain the comparison. Keep the
geometry executor, primitives, tolerances and gpt-6-sol medium policy fixed. Judge
visual coherence and meaningful separation independently of numeric checks. This is
research, not production promotion or proof of autonomous component discovery.

## Changes and frozen sequence

1. Use background Responses with store=false, saving the acknowledged response ID
   durably. Retrieve that same job after a polling interruption; never repeat creation
   after an unknown outcome. Keep the original $0.1405625 synchronous timeout hold.
   That old call has no saved response ID and cannot be recovered by this implementation.
   A new, explicitly bounded drone planning trial measures the new transport.
2. Repair the unchanged initial Assembly 010 fan once with a model-authored patch.
   Compute allowed shapes/ports from failed measurements, including all shared-shape
   consumers. Protect unrelated local geometry exactly. No part, role, requirement,
   connection or group deletion/replacement. No weaker tolerances. Run full geometry,
   coverage, global arrangement, all-pair collision and preserved-fact checks afterward.
3. Extract the original speaker request with compact typed keys, retaining all schema
   constraints. Required front-face intent must map honestly or remain unsupported.
   Do not change its phrase, force planar contact, add speaker-specific handling or
   reinterpret an invalid returned value by hand.
4. Reuse the valid 34-record drone interpretation from 011 and request one fresh initial
   plan through recoverable transport. Plan the speaker only if its interpretation is
   admitted. Each new executable failed candidate gets at most one local patch.

The fan goes first to test small repairs without another complete starting-plan call.
Whole initial plans are still permitted for newly built families. All geometry checks
remain global; this experiment does not claim incremental geometry execution. The
geometry executor combines construction and some checks, so traces explicitly record
that combined time rather than fabricate separate durations. Record model/parse timing,
usage, proposed forms/parts, failed IDs, patch changes/protected parts, polling and
cancellation events. Compare renders assembled/exploded; no manual geometry repair.

## Recovery and spending

One creation per operation. Durable request/body fingerprint, response ID, terminal
response and usage settlement precede further work. GET errors pause for retrieval of
that existing job. A missing creation acknowledgement, usage mismatch, funding error
or spending failure stops the batch. No guessed billing or automatic creation retries.
A malformed completed response rejects that case; other independent admitted cases may
continue. A saved terminal response can settle once after interruption.

Cancel a known job at a 360-second research deadline; each network exchange has a
30-second timeout. Cancellation/retrieval can extend wall time past the deadline.
Recoverability does not relax product latency acceptance or imply lower latency.
Background store=false temporarily retains response data for polling (roughly ten
minutes per official documentation); it is not indefinite offline recovery. If retrieval
expires or terminal usage is absent, retain the reservation. Cancellation is not a refund.

Six paid operations maximum: fan patch <=$0.12, speaker extraction <=$0.045,
two initial plans <=$0.16 each, two patches <=$0.12 each. Sum of maxima $0.725;
batch ceiling $0.78, conservative prior allowance $4.20, aggregate ceiling $5.00,
shared daily cap $6.00. Exact-input quote and maximum-output reservation before creation.
Extraction allowance 3,072 output tokens; initial plans 12,288; local patches 6,144.
No model change, GPU, paid judge, wider token cap or silent additional experiment.

## Decision

A local repair succeeds only if it addresses the recorded failures, preserves all
previously passing facts and unrelated local geometry, passes the complete unchanged
checks, and produces a visually coherent object with useful parts. Fewer generated
fields or a successful background job alone is not success. If correct declared intent
still yields malformed or visually inadequate assemblies, reconsider the construction
method before adding representation or geometry capabilities. Retain every failure.
