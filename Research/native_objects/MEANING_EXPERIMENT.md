# Meaning 005 — bounded interpretation test

Test the distinction between appearance, meaningful static structure, demonstrated
behavior, physical verification and exact identity before spending on more geometry.
Keep the geometry executor unchanged. This is an extension of the existing research
requirement inventory, not a new object format, production route or model judge.

The compiler supplies a mode and basis for each existing requirement ID. Explicit,
inferred and design-choice origins remain distinct. Exact quoted exclusions retain
waived scope without deleting unrelated requirements. The validator rejects typed
contradictions and mode substitutions. Registry admission detects required unsupported
capabilities, unexpressible constraints or missing evidence before construction
planning. Optional unsupported requirements are disclosed without becoming mandatory.
Appearance coverage remains visually unverified; consistency is not entailment.

Use one generic instruction for seven predeclared cases in `meaning_cases_005.json`:
a novel static hanging-sphere concept; the same concept animated; the same concept
with verified load capacity; original lamp; original drone; static controller;
exact-product internals. The first three vary intent while retaining the core object.
Fixed proposed role lists isolate requirement interpretation. Familiar role lists
are replayed; new contrast/controller/exact-case role lists are authored test inputs,
not evidence of automatic role discovery or end-to-end generation. No expected
assertion, object recipe, old construction or corrected inventory enters the model.

Each output is checked against frozen benchmark assertions, then inspected against
its source. Keyword checks for visible poses are limited benchmark assertions,
not general runtime interpretation. Requiredness matters in manual source review.
No model grades its own completion. No paid geometry or reviewer calls in this batch.
A pass requires all dispatched cases valid, expected distinctions preserved and
no source-review contradiction. Missing/unattempted cases are not passes. A static
concept should not acquire a physics requirement; requested effects must remain
required and explicitly unsupported if unavailable. Exact identity needs evidence.

Existing gpt-6-sol medium, 3,072 output tokens, $0.045 admission ceiling per case.
One call per fixed case; no automatic retry. $0.13 batch ceiling, unchanged $2 UTC
daily/$5 aggregate research limits; conservative prior allowance $2.60. At freeze
$0.136025 remained in the shared daily ledger. Calls can be blocked because the
remaining budget cannot cover their maximum reservation. No budget or token raises.
Unknown outcomes stay reserved and unknown billing halts dispatch. Fixed IDs prevent
repeat generation. Price expiry/model/tier checks remain active. Freeze code, cases,
schema, instructions and geometry hashes. Save invalid outputs and costs too.

Decision: if meaning still collapses, change the general interpretation contract or
policy, not individual outputs. First use free local failure tests and preserve live
failures. If distinctions hold, retain this admission layer; that does not establish
visual quality or complete generation. Implied constraints without an executable
adapter remain visible limitations, not permission to expand geometry automatically.

uses a capability label with qualifiers and an unsupported capability-target field;
drone/controller copy role names as quotes not present in the request. All seven
responses completed and cost $0.0991275. Original outputs are retained unchanged.

General correction: the compiler selects application-assigned source-segment IDs;
code resolves exact text and rejects unaccounted segments. This is segment coverage,
not proof every phrase was understood. Canonical capability names/empty targets are
constrained with nested schema alternatives; dynamic relational constraints use
explicit unsupported behavior requirements with entity targets. Unknown operations
remain unsupported. No geometry or answer is injected to rescue a case. The
[documented Structured Outputs subset](https://developers.openai.com/api/docs/guides/structured-outputs)
supports these nested alternatives; schema conformance still does not prove meaning.

an explicit bounded protocol amendment after observed failures, not a claim that
