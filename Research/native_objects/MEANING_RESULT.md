## General correction, without rewriting outputs

The compiler now selects stable application-assigned source-segment IDs. Code
resolves those references to the exact original words, rejects invented references,
and requires every segment to be accounted for. This prevents fabricated quotations
and dropped whole segments. It does not prove that every phrase was interpreted
correctly or that an inference follows from its cited segment.

Nested typed alternatives constrain capability names to canonical runtime actions.
Qualifiers and relationships that must persist during action remain separate behavior
requirements, with explicit targets and unsupported status when necessary. They
cannot masquerade as a static attachment or implemented animation. Physical and
identity claims still require evidence; optional unavailable work stays optional.
These constraints use the documented [Structured Outputs subset](https://developers.openai.com/api/docs/guides/structured-outputs),
which constrains form rather than semantic truth.

Source references, exclusions and interpretation fields are frozen with the existing
requirement contract. Existing construction orchestration accepts this inventory and
performs capability admission before requesting a geometry plan. Original inventory
formats remain replayable. This remains research code, not a promoted production
object route or a new object-package format.
