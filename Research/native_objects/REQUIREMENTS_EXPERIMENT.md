# Intent preservation 004 — bounded protocol

Question: can ORYN preserve important user intent from the original request through
an executable construction plan without silently dropping requirements?

The application calls its existing OpenAI model. Codex supplies no per-output
geometry repairs, bindings, inventories or manual corrective values. Same four
lamp/drone/speaker/sharpener requests and replayed semantic role proposals as 003.
The sharpener is now a known case. Exact-product request remains evidence-blocked.
No new geometry operations, providers, models, GPU work or product integration.

## Pipeline and deterministic gate

1. Extract compact requirements from the original request with source quotes and
   stable IDs. Each proposed role receives an entity ID and existence requirement.
   Required, optional, design choice and evidence-required remain distinct.
2. Validate exact source quotes, types and references; freeze the inventory and
   original request hashes. No paid extraction retry in this experiment.
3. Plan using that immutable inventory. Bind every ID to actual part instances,
   typed containment/connection/clearance relationships, an implemented capability,
   or explicit unsupported with reason. Unsupported does not erase requiredness.
4. Missing or invalid bindings block geometry and permit one bounded plan repair.
   Required/evidence-required unsupported results block geometry without pretending
   repair can add an unsupported executor capability. Optional unsupported is visible.
5. Only a complete gate with no blocking unsupported item may call the unchanged
   geometry executor. Geometry requirements freeze before that call; subsequent
   repairs cannot weaken them. Numeric failure is distinct from coverage failure.

The gate verifies references, endpoint direction, instance counts, mate paths and
registered capabilities, rather than asking another model to judge completeness.
Appearance bindings only establish responsibility; rendered appearance is unverified.
Source quotes establish traceability, not entailment or extraction completeness.
Post-run source review is separate and never fed back as handcrafted corrections.
A role proposed earlier is not automatically a user requirement: the compiler must
classify it. Omitting optional/design-choice roles must remain disclosed and is not
evidence that all useful components were generated.

## Compact output and observed token limit

003 speaker: 12,288 output tokens, 10,438 reasoning (84.9%). Sharpener: 12,288 output,
9,528 reasoning (77.5%). Both responses were incomplete at max_output_tokens.
This is evidence of output-budget exhaustion, not request timeout or credit failure.

Use existing gpt-6-sol at medium reasoning for extraction and planning. Extraction:
4,096 output tokens, $0.055 admission ceiling. Construction: unchanged 12,288 output
tokens, $0.16 admission ceiling. No paid reviewer. Request-specific shared shape
records, omitted defaults and solved nonroot poses reduce repeated serialization.
The adapter expands into the existing geometry contract. It contains no object
recipes. Offline previous-output roundtrip audit is never shown to the live model.
Its byte counts exclude new requirement bindings and are not token measurements.
Effort, staging and representation all change; this is not a causal ablation.

## Spend and ordering

Four extractions, then four initial plans, then eligible single repairs. A missing
binding can be repaired, an explicit mandatory unsupported result stops that case.
Provider incomplete/invalid responses or ambiguous delivery are not automatically
retried. All ambiguous costs remain reserved, unknown billing halts shared ledger.
$0.50 batch cap including reservations, unchanged $2 UTC daily and $5 aggregate
research limits, conservative prior research allowance $2.20. No cap increases.
Admission may prevent later calls even if actual earlier costs are small. That is
reported as a budget-blocked attempt, not as a model or geometry failure.
240-second request timeout, 256 KiB response bound. Exact input counting, model/tier/
usage reconciliation and price expiry remain active. Fixed operation IDs prevent
accidental repeat spending. Executor hashes are checked before each live call.

## Predeclared assessment

Record separately, for every case:
- Source intent extraction: pass, partial or fail against the unchanged request;
  retain the lamp's seed-inside-shade relation, suspended placement, appearance and
  relevant behavior explicitly. This checklist is evaluation only, not model input.
- ID coverage: complete / missing-invalid / complete with blocking unsupported.
- Geometry execution: prevented / attempted; numeric and visual result separately.
- Output completion, reasoning vs other output tokens, call and build timings,
  repairs, estimated token charges and held reservations.

Pipeline success requires no important source intent missing, valid bindings and
supported geometry realization. Explicit unsupported demonstrates honest intent
retention but does not count as a generated-object success. Coverage-only success
cannot conceal poor appearance, wrong requirements or missing engineering behavior.

If extraction drops intent, address requirement extraction before geometry changes.
If coverage fails, address binding/planning reliability. If complete plans cannot
realize required geometry, report that specific downstream limitation. Do not
expand the executor, raise token limits, launch new providers or add more paid
experiments automatically. Preserve every attempt and the frozen protocol.
